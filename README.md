# Kirby Knowledge

**你不需要整理知识，只需要把东西交给它。**

## ✦ 为什么做

我们每天都会遇到大量信息：

一篇文章、一本 PDF、一段聊天、一个突然想到的概念……

真正麻烦的却不是**找到信息**，而是：

> **哪些东西值得留下？**

传统知识库往往要求你自己分类、整理、打标签、建立目录。

Kirby Knowledge 想做的事情恰好相反：

**把整理的负担交给系统。**

你只管把东西喂给卡比。

---

## 🍴 卡比是怎么工作的

```text
                你遇到一个东西
                       ↓
                   喂给卡比
                       ↓
                  👄 卡比吃下
                       ↓
                 判断是否值得记住
                       ↓
          ┌────────────┴────────────┐
          ↓                         ↓
       不值得                    值得留下
          ↓                         ↓
     不形成长期记忆             形成 Memory
                                    ↓
                              保留必要来源
                                    ↓
                               随时搜索回来
```

它不是把所有东西都塞进数据库。

它首先关心的是：

> **“这个东西，以后还值得记住吗？”**

## ✨ 现在能做什么

### 🍴 喂知识

目前可以直接投喂：

* 文本
* TXT
* Markdown
* Chat 聊天记录
* 网页 / URL
* PDF

不需要提前分类，也不需要自己整理目录。

---

### 🧠 自动形成长期记忆

系统会判断输入是否值得成为长期记忆。

值得的内容会形成 Memory。

没有长期价值的内容可以不留下长期 Memory。

这意味着：

> **“记住 0 条”也是正常结果。**

---

### 🔎 记忆可以追溯来源

每条 Memory 都可以回到它真正来自的 Source：

```text
Memory
  ↓
来自
  ↓
Source
  ↓
原始内容
  ↓
这个来源形成了哪些 Memory
```

所以它不是只告诉你：

> “我记得这个。”

还可以告诉你：

> “我是从哪里记住它的。”

---

### 🔍 搜索你的记忆

你不需要记住当初把东西放在哪里。

直接搜索：

> **你还记得什么？**

找到 Memory，再回到它的来源。

---

## 🐾 为什么是卡比

因为我不想做一个看起来像数据库的知识库。

我更想做一个：

> **真的像在“喂东西”的知识系统。**

所以在 Kirby Knowledge 里：

```text
你          →      卡比
喂知识      →      吃掉
处理        →      消化
形成记忆    →      吃饱了~
```

卡比不是一个装饰。

**它就是这个产品和传统知识库最直观的区别。**

## 🏠 Local-first

Kirby Knowledge 的数据主要保存在本地。

目前的核心数据使用 SQLite 存储，搜索也在本地完成。

模型调用只发生在需要模型参与记忆形成的环节。

这意味着：

* 不需要为了搜索记忆而持续调用模型
* 不需要向量数据库才能使用基本搜索
* 不需要把整个知识库交给云端才能工作

当然，**当你投喂内容进行记忆形成时，内容会发送给你配置的模型服务。**

---

## 🚧 还没有做什么

Kirby Knowledge 1.0 并不是一个“什么都有”的 AI 知识库。

目前还没有：

* 图片理解
* OCR
* 向量 / 语义搜索
* RAG
* AI 对话式知识问答
* 自动知识整理
* 知识图谱
* 自动建立完整知识结构

这些东西不会因为“看起来很 AI”就全部塞进 1.0。
