**你不需要整理知识，只需要把东西交给它。**

## ✦ 为什么做

我们每天都会遇到大量信息：

一篇文章、一本 PDF、一段聊天、一个突然想到的概念……

真正麻烦的却不是**找到信息**，而是：

> **哪些东西值得留下？**

传统知识库往往要求你自己分类、整理、打标签、建立目录。

Kirby Knowledge 想做的事情恰好相反：

**把整理的负担交给系统。**

你只管把东西喂给卡比。

---

## 🍴 卡比是怎么工作的

```text
                你遇到一个东西
                       ↓
                   喂给卡比
                       ↓
                  👄 卡比吃下
                       ↓
                 判断是否值得记住
                       ↓
          ┌────────────┴────────────┐
          ↓                         ↓
       不值得                    值得留下
          ↓                         ↓
     不形成长期记忆             形成 Memory
                                    ↓
                              保留必要来源
                                    ↓
                               随时搜索回来
```

它不是把所有东西都塞进数据库。

它首先关心的是：

> **“这个东西，以后还值得记住吗？”**

## ✨ 现在能做什么

### 🍴 喂知识

目前可以直接投喂：

* 文本
* TXT
* Markdown
* Chat 聊天记录
* 网页 / URL
* PDF

不需要提前分类，也不需要自己整理目录。

---

### 🧠 自动形成长期记忆

系统会判断输入是否值得成为长期记忆。

值得的内容会形成 Memory。

没有长期价值的内容可以不留下长期 Memory。

这意味着：

> **“记住 0 条”也是正常结果。**

---

### 🔎 记忆可以追溯来源

每条 Memory 都可以回到它真正来自的 Source：

```text
Memory
  ↓
来自
  ↓
Source
  ↓
原始内容
  ↓
这个来源形成了哪些 Memory
```

所以它不是只告诉你：

> “我记得这个。”

还可以告诉你：

> “我是从哪里记住它的。”

---

### 🔍 搜索你的记忆

你不需要记住当初把东西放在哪里。

直接搜索：

> **你还记得什么？**

找到 Memory，再回到它的来源。

---

### 📚 从 Memory 开始学习

在 Memory 详情页点一下：

> **学习这一条**

卡比就会以这条 Memory（以及它所在的材料）为内容，开始一次学习。

学习状态只由学习引擎写入，页面只负责如实显示。

---

### 🤖 和 Teacher 对话

进入学习后，你可以直接和 Teacher 说话。

它会解释、追问，也可能请你复述。

> Teacher 是基于真实 LLM 的学习助手，会根据当前学习状态进行解释、提问和学习记录。

---

### 📈 学习进度会被记录

当一次学习真的发生（你表示理解了，或 Teacher 认为可以记录），它会把这次学习记下来：

```text
这一条学了没有
理解到什么程度
这次学习走到哪一条了
```

---

### 💾 学习状态会保存下来

学习状态存在本地数据库里，不在页面里。

所以：

* 刷新页面，进度还在
* 关掉程序再打开，还能从这里继续
* 一次失败（比如模型给出的记录不合法）不会弄坏这次学习

## 🎓 卡比是怎么陪你学习的

1.1 开始，记忆不只是被“记住”，还可以被拿来学习。

```text
Memory
   ↓
开始学习
   ↓
Teacher
   ↓
通过对话理解知识
   ↓
学习状态被记录
   ↓
下次（刷新或重启之后）继续
```

整个过程都在网页里完成：

```text
打开知识库
   ↓
看到一条知识
   ↓
点「学习这一条」
   ↓
开始学习
   ↓
问 Teacher 一个问题
   ↓
Teacher 回答
   ↓
触发学习记录
   ↓
看到进度变化
```

你不需要知道它是怎么实现的，也不需要理解任何内部结构。

**你只需要点一下「学习这一条」，然后开始聊。**

---

## 🐾 为什么是卡比

因为我不想做一个看起来像数据库的知识库。

我更想做一个：

> **真的像在“喂东西”的知识系统。**

所以在 Kirby Knowledge 里：

```text
你          →      卡比
喂知识      →      吃掉
处理        →      消化
形成记忆    →      吃饱了~
```

卡比不是一个装饰。

**它就是这个产品和传统知识库最直观的区别。**

## 🏠 Local-first

Kirby Knowledge 的数据主要保存在本地。

目前的核心数据使用 SQLite 存储，搜索也在本地完成。

模型调用只发生在需要模型参与的环节：判断一段内容是否值得记住，以及和 Teacher 对话。

这意味着：

* 不需要为了搜索记忆而持续调用模型
* 不需要向量数据库才能使用基本搜索
* 不需要把整个知识库交给云端才能工作

当然，**当你投喂内容进行记忆形成、或和 Teacher 对话时，相关内容会发送给你配置的模型服务。**

## 🚧 还没有做什么

Kirby Knowledge 1.1 并不是一个“什么都有”的 AI 知识库。

目前还没有：

* 图片理解
* OCR
* 向量 / 语义搜索
* RAG
* 流式回答（Streaming）
* 聊天记录（Chat History）
* 多 Agent（Multi-Agent）
* 自动知识整理
* 知识图谱
* 自动建立完整知识结构

这些东西不会因为“看起来很 AI”就全部塞进 1.1。
